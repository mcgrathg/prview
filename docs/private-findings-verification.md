# Private investigation findings — 2026-11-08

The investigation preview (`?organize=1&investigate=1`) adds a compact Findings/Jot entry in its existing row and Save evidence on source panes. Its collapsible drawer keeps freeform notes, optional Question/Observation/Concern labels, immutable source references and a resumable investigation checkpoint. Findings aggregate per PR, retain their originating question and survive closing the question. Main, preview and kept code can contribute evidence; evidence inspection opens a temporary preview while preserving main.

The notebook is a separate PR-keyed actor/storage boundary. Body text never enters investigation URLs or checkpoint projections. Each finding has its own localStorage record, so successful writes from two tabs cannot overwrite unrelated records through a shared index. Existing whole-notebook preview data is read and retained without rewriting its bytes. Changes to the same finding use its most recent stored record; this is browser-local storage, not collaborative document editing or account sync. Storage events merge visible records. Malformed records are quarantined before writes, and storage failures leave notes in memory with a copy/retry warning. Bounds retain existing work and show a notice rather than dropping an old finding.

Source capture uses actual displayed immutable bytes and an ordered selection range. Endpoints at a following row’s start exclude that unselected row; endpoints after row code retain it. The full selected line range stays attached to the reference; only its excerpt is bounded to 32 lines/8000 characters and labeled when shortened. Pinned GitHub links retain full SHA and range. Earlier-revision evidence remains anchored and labeled as the PR advances.

Prepare review draft appends explanation and evidence links through the existing reviewDrafts store. It preserves prior text and attachment links, then opens the native MarkdownComposer. Conversion does not enqueue a mutation. Publication remains an explicit native action with current-head and comparison eligibility guards; stale draft targets stay visible. Existing shortcut/footer confirmation rules are unchanged.
