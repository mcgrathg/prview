# Native GitHub review attachments

Cockpit uploads media to GitHub's repository-associated attachment store, then inserts the returned URL into the original review draft. Uploading and submitting a comment are separate actions. The adapter independently implements the wire contract used by the MIT-licensed GitHub CLI; it uses a captured personal credential held on the server.

## Provider contract

GitHub documents image/video attachments through `gh --attach`, with repository push access required. Selecting or pasting a file uploads it before the comment is submitted. GitHub documents public-repository attachments as publicly readable and private/internal attachments as requiring repository access. Treat public-repository uploads as public even when an unposted asset is not yet readable anonymously. [CLI attachment documentation](https://docs.github.com/en/github-cli/github-cli/attaching-files-with-github-cli), [GitHub attachment policy](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files)

The inspected first-party uploader is pinned to CLI commit `736c68f674113337685e3eb1f908602a03b8f99b`. It sends raw bytes to `POST https://uploads.github.com/user-attachments/assets`, with `name`, `content_type` and numeric `repository_id` query parameters. Headers include the captured GitHub credential, `Content-Type: application/octet-stream`, `Accept: application/vnd.github+json` and the exact length. A successful response supplies the attachment URL. This is an observed first-party implementation contract, not a separately versioned REST guarantee. [Uploader source](https://github.com/cli/cli/blob/736c68f674113337685e3eb1f908602a03b8f99b/internal/attachments/client.go), [transport tests](https://github.com/cli/cli/blob/736c68f674113337685e3eb1f908602a03b8f99b/internal/attachments/client_test.go)

The CLI uploader has no attachment delete endpoint or automatic retry. Removing a draft therefore preserves the remote asset. Credential acceptance also remains a server decision; a 404 is not proof that repository write access alone will fix the request. [Upload orchestration](https://github.com/cli/cli/blob/736c68f674113337685e3eb1f908602a03b8f99b/internal/attachments/attach.go), [CLI v2.103.2](https://github.com/cli/cli/releases/tag/v2.103.2)

## Cockpit boundary

`GET /api/pr/:owner/:repo/:number/attachments` returns capability, reason, repository identity/visibility, account identity, allowed MIME types and the byte limit. `POST` accepts one multipart `file` plus expected `accountId`, `repositoryId` and `visibility`. One captured personal credential rechecks the repository and permissions, verifies those identities, then uploads. Tokens and upload destinations never come from the browser. Existing origin and replica rules apply.

PNG/JPEG/GIF and MP4/MOV/WebM are supported up to 10 MiB each. SVG/WebP exclusion and the conservative video ceiling are local product limits. Filename, MIME and media-signature checks reject mismatches; they are not full codec validation. The server bounds the multipart body, sanitizes the basename, disables redirect following and accepts only HTTPS `github.com/user-attachments/assets/...` results.

The composer names the repository, account, visibility and immediate-upload timing before file choice, paste or drop. Progress, cancellation and manual retry preserve its text. A successful response inserts Markdown at the captured selection, or appends the URL if the text changed. Draft actors synchronize completed uploads; stale typing and late completion after unmount retain unseen attachment URLs. Intentional text removal remains possible. Uncertain uploads warn that GitHub may already have accepted the file; retry stays explicit. Upload responses participate in the shared quota cooldown, including `Retry-After`.

## Verification recorded on 2026-11-07

The focused adapter/composer suite and independent review passed 24 tests and 112 assertions. Tests cover raw transport, credential capture, stale account/repository/visibility, read-only permissions, body/type limits, response URLs, cancellation, concurrent drafts and secondary cooldowns. The real capability read for Storybook #36948 reports READ access and the UI displays its write-access requirement.

After account authorization, the real adapter uploaded the prepared 79-byte PNG to public `mcgrathg/danger-plugin-jira-integration#3` as `mcgrathg` and returned HTTP 201. Its returned Markdown rendered a complete 16×16 image in the composer preview; the authenticated image proxy returned the identical SHA-256 and byte length. The unposted asset returned 404 anonymously, so the disclosure now tells reviewers to treat public-repository uploads as public while allowing access before comment submission to vary. Private-repository access was not tested. No comment was submitted. The browser automation file-chooser bridge lost its tab before transfer; this live transport/rendering check used the actual multipart endpoint and placed its returned Markdown into the composer. Picker/paste/drop insertion and failure recovery retain their focused automated coverage.
